# Firefox YouTube Downloader v2.5.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v2.5.0 with a separate video folder, robust audio extraction across yt-dlp extractors, explicit apt dependency installation, and repeatable Linux package assets on each tagged release.

**Architecture:** Preserve the current Python/Bash companion and Firefox popup. Add `video_download_dir` beside the existing audio `download_dir`; make audio selectors use yt-dlp's `/best` fallback and constrain FFmpeg remux/encode mappings to audio plus attached cover art. Keep package builders separate from the per-user installer, with system-wide Firefox Native Messaging manifests for distro packages. A tag workflow builds and attaches packages to a draft release that already contains the AMO-signed XPI.

**Tech Stack:** Python 3, Bash, Firefox WebExtension, yt-dlp, FFmpeg/ffprobe, Debian `dpkg-deb`, Fedora `rpmbuild`, Arch `makepkg`, GitHub Actions, AMO `web-ext` signing.

**Spec:** `docs/superpowers/specs/2026-11-14-v2.5-downloads-linux-packaging-design.md`.

## Global Constraints

- Bump the Firefox extension and Native Messaging host to `2.5.0`; package version is read from `extension/manifest.json` and must match tag `v2.5.0`.
- Fresh video path is `~/Videos/Youtube Downloads`; audio path behavior stays `~/Music/Youtube Downloads` unless an existing yt-dlp config applies or the user selects another path.
- `video_download_dir` missing in pre-v2.5 config migrates to `~/Videos/Youtube Downloads`; explicit `null` means use yt-dlp paths if configured, otherwise fall back to the project video default.
- Audio selectors: `bestaudio/best`; Opus: `bestaudio[acodec=opus]/bestaudio/best`; M4A: `bestaudio[ext=m4a]/bestaudio/best`.
- Never map ordinary video streams into audio-only outputs; preserve audio metadata and attached pictures where the chosen container supports them.
- `install.sh --install-deps` is explicit opt-in and Debian-family only; core/tagging dependencies install by default; `rsgain` is included only with `--with-rsgain`.
- Package IDs/files: `firefox-youtube-downloader-companion`; `.deb` `all`; Fedora RPM `noarch`; Arch recipe bundle includes `PKGBUILD` and generated `.SRCINFO`.
- Package manifests are system-wide and absolute-path; package lifecycle scripts never write to a user's home, yt-dlp config, or Firefox profiles.
- Release assets: signed XPI, `.deb`, Fedora `.rpm`, tagged source tarball, Arch recipe archive. The tag workflow attaches packages to an existing draft; publish only after verification. Keep `install.sh` as the per-user fallback.
- Defer AppImage, Flatpak, Snap, Nix, Alpine APK, and repository submissions to AUR/COPR/OBS.

## Review Focus

1. A v2.4 config migrates to the new video default without changing its audio directory; explicit `null` still defers to yt-dlp config (Task 1 tests).
2. Dailymotion-like muxed-only sources select `/best`; audio/cut FFmpeg output has audio and attached art but no ordinary video stream (Task 2 generated-media tests).
3. Invalid `--install-deps` combinations or non-Debian platforms fail before running a privileged command; default installs include tag dependencies but not rsgain (Task 3 fake-apt tests).
4. Distro packages install a host manifest pointing to an absolute existing script and do not write per-user paths (Task 4 package layout tests).
5. Release package versions, filenames, checksums, and tag agree; failed/missing package jobs do not publish a draft release (Task 4 workflow checks).
