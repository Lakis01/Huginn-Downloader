# v2.5.0 Download Progress Implementation Plan

> **For agentic workers:** Use the executing-plans skill to implement this plan task-by-task. Each task uses a test-first cycle.

**Goal:** Show live yt-dlp progress and ETA by default in the download terminal, while adding a persistent opt-in verbose-output setting.

**Architecture:** Keep `--quiet --progress` as the default, but stream stderr chunks from the yt-dlp child to the terminal while retaining bounded diagnostic text for retries. Add a backward-compatible `verbose_output: false` config setting; when enabled, pass `--verbose` rather than `--quiet` on audio, video, and cut downloads.

**Tech Stack:** Python subprocesses, yt-dlp, Firefox WebExtension popup, unittest, Node popup fixtures.

**Spec:** `docs/superpowers/specs/2026-11-14-v2.5-download-progress-design.md`.

## Review Focus

1. A progress update ending in `\r` is forwarded before yt-dlp exits; a later stderr line does not overwrite earlier output in the captured error tail.
2. Authentication errors remain recognized and trigger one Firefox-cookie retry after introducing streaming.
3. A missing `verbose_output` config stays false; invalid non-boolean values are rejected/ignored consistently with other config booleans.
4. Audio, video, and cut commands keep progress enabled and switch between exactly one of `--quiet` or `--verbose`.
5. Popup changes persist only `verbose_output` and explain that quiet mode still shows progress in the terminal.
