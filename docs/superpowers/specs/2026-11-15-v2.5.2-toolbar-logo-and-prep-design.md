# Huginn Downloader v2.5.2 — Toolbar Logo, README Parallel Downloads, and Local Prep Design

## Intent

Prepare Huginn Downloader so the maintainer can install a newly AMO-signed extension with the full layered raven icon, run it against an up-to-date local companion (`2.5.2`), capture three new screenshots (watch-page pill, context menu, and toolbar popup), and prepare the repository for public release and sharing on Reddit.

## Goals and Non-Goals

- **Toolbar and root menu icon:** Use `docs/logo/huginn-logo.svg` directly as `extension/icons/huginn-logo.svg` for the extension's toolbar button, add-on metadata icons (`16`, `32`, `48`, `96`), and context-menu root item (`ytdl-root`), removing the simplified `extension/icons/plugin.svg`. Keep `extension/icons/audio.svg`, `extension/icons/video.svg`, and `extension/icons/cut.svg` unchanged.
- **Version bump for AMO signing:** Bump `extension/manifest.json` and `bin/yt-dlp-native-host.py` to `2.5.2` so Mozilla AMO signs a fresh unlisted XPI containing `icons/huginn-logo.svg` instead of returning `409` (`Version 2.5.1 already exists.`) and fetching the older `2.5.1` artifact.
- **README and GitHub home page:** Keep `docs/logo/huginn-logo.webp` embedded at the top of `README.md` so it renders on the GitHub repository home page, and document clearly in `README.md` that downloads run independently in parallel without waiting for an earlier download to finish. Update `docs/BACKLOG.md` accordingly.
- **Local directory rename:** Rename `/home/gratis01/Programs/Youtube Downloader` to `/home/gratis01/Programs/Huginn Downloader` and run `git worktree repair` so linked OpenCode git worktrees continue resolving cleanly.
- **Local companion upgrade and XPI signing:** Update the maintainer's local `~/.local/bin` companion installation to `2.5.2` via `./install.sh --install --yes` (preserving existing user `config.json` and `yt-dlp` configuration), then sign `dist/huginn-signed.xpi` via `./scripts/sign-xpi-kwallet.sh` without exposing KWallet credentials.
- **Non-goals:** Do not alter the published `v2.5.1` tag or release, do not create a `v2.5.2` tag or GitHub release yet (hold release publication until the maintainer provides the three screenshots), and do not change repository visibility to public yet.

## Constraints

- Preserve Firefox add-on ID `firefox-youtube-downloader@lakis01.github.io`, Native Messaging host ID `firefox_youtube_downloader`, OS package IDs, configuration paths, and install paths.
- Keep AMO credentials strictly inside KDE Wallet (`Huginn Downloader` folder, entries `AMO_JWT_ISSUER` and `AMO_JWT_SECRET`); never print, log, or persist secret values.
- Extension source files checked by `tests/test_firefox_extension.js` must remain ASCII-only (except em/en dashes) with no emoji.

## Approaches

1. **Bump to `2.5.2`, ship `huginn-logo.svg` directly in `extension/icons/`, update local companion, and sign without tagging (chosen).** Gives AMO a fresh signable version, keeps companion and popup versions aligned (`Connected (companion 2.5.2)`), lets the maintainer test the exact layered SVG in Firefox's toolbar, and leaves `dist/huginn-signed.xpi` ready both for immediate installation/screenshots and for a later `v2.5.2` release tag.
2. **Keep `manifest.json` at `2.5.1` and build an unsigned XPI.** Standard Firefox release builds refuse unsigned XPIs, and `scripts/sign-xpi.sh` on `2.5.1` downloads the already-signed `2.5.1` archive with the old icon.
3. **Leave `~/.local/bin` at `2.0.0`.** Connects over Native Messaging, but shows `Connected (companion 2.0.0)` in popup screenshots and lacks `2.5.x` video/XDG presets and config keys.
