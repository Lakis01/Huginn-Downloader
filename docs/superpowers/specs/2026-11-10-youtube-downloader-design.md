# YouTube Downloader, Tagging, and Firefox Integration

## Intent

Make the user's YouTube audio, video, and interactive-cut workflow produce dependable files in `~/Downloads`, with accurate description-derived music metadata, individual-track ReplayGain, and reliable Firefox/KDE launch paths.

## Goals

- Recognize official YouTube Art Track descriptions and write all useful structured credits and release data from the description.
- For ordinary uploads, use the uploader/channel, a cleaned title, and the video's upload date as fallback metadata.
- Preserve a human-readable collaboration/featuring string in `artist`, while writing the individual artist names as a multi-value `artists` tag.
- Run `rsgain` in individual-track write mode for audio and cut outputs.
- Fix KDE launcher entries and offer conflict-free keyboard shortcuts that use the active YouTube media URL without requiring clipboard copying.
- Keep External Application Launcher context actions available on YouTube page, frame, link, image, audio, and video contexts; provide persistent Tampermonkey player buttons through an OS URL handler.
- Keep `yt-to-forerunner` compatible with the shared metadata parser.

## Non-goals

- Do not modify or replace Firefox's signed External Application Launcher add-on.
- Do not automatically alter KDE keyboard bindings; provide exact setup instructions and let the user set them in System Settings.
- Do not add a new media library, network service, background daemon, or dependency that is unavailable on the host.
- Do not rewrite metadata on video-mode downloads beyond the existing yt-dlp video behavior.

## Constraints and metadata contract

- Work from `~/Programs/Youtube Downloader`; keep source, tests, setup instructions, and installation assets there.
- Retain `parse_info(info)` compatibility keys used by `~/.local/bin/yt-to-forerunner`: `artist`, `title`, `album`, `date`, `composer`, `is_tagged`, and `duration`.
- `date` and `originaldate` must be `YYYY`, `YYYY-MM`, or `YYYY-MM-DD`; use the official description's `Released on:` value before the video upload date. A distinct earlier ℗ year is stored as `originaldate`.
- Preserve a featuring credit verbatim in `artist` (for example, `Artist A featuring Artist B` or `Artist A feat. Artist B`). Write the distinct names as multi-valued `artists` tags. Do not split `&` that belongs inside an artist name.
- Save audio/cut outputs with safe `Artist - Title` names; remove temporary info/thumbnail sidecars after tagging.
- Use `rsgain custom -s i` one output file at a time. Leave rsgain's default ReplayGain/Opus mode rather than imposing the optional `-o r` mode.
- Do not import a partial External Application Launcher export: its import replaces all extension settings. Document safe per-app manual changes instead.
- The on-page buttons use the `yt-dlp://` OS URL handler and Firefox's external-application confirmation. The signed External Application Launcher add-on has no supported direct page-script launch bridge.

## Approaches considered

1. **Direct Python tagging with Mutagen/Pillow, plus an OS URL handler for Tampermonkey buttons (chosen).** It avoids yt-dlp postprocessor ordering conflicts, supports native multi-value tags and cover art, and gives the buttons a supported OS launch path. Firefox may ask to open the external application.
2. **yt-dlp metadata flags plus an External Application Launcher page bridge.** Rejected because postprocessor ordering can overwrite dates/FFmpeg arguments, and the installed signed extension does not expose a direct page-script API for invoking a saved app.
3. **Local HTTP service as the button bridge.** Rejected because it adds an always-running service and a browser-to-localhost security boundary for a workflow that can use a user-confirmed custom scheme.

## Tagging behavior

- Official Art Tracks are identified by both `Provided to YouTube by` and `Auto-generated by YouTube.` in the description.
- Parse title and primary/collaborating artists, album, `Released on:`, ℗/© lines, distributor, ISRC, genre, recording date/studio, and role-labelled credits including composer/writer, lyricist, producer, performer/instrument, arranger, conductor, publisher, label, and recording/mixing/mastering engineering roles where present.
- For collaborations, preserve the display credit string. `artists` is a multi-value field; all other credit roles are multi-value when several people/organizations are listed.
- Non-Art-Track audio uses cleaned uploader/channel and video title, parses a leading `Artist - Title` when present, extracts featuring credits, and uses the video's upload/release date as the fallback date.
- Art Track landscape thumbnails are center-cropped to square front cover art; fallback thumbnails retain their original aspect ratio.
- Clear description, URL, synopsis, and free-form comment data from the resulting audio tags.

## Firefox and KDE behavior

- KDE shortcuts: `Meta+Alt+A` (audio), `Meta+Alt+V` (video), `Meta+Alt+C` (cut). The active media URL is obtained from Plasma Browser Integration/MPRIS, with clipboard fallbacks. Right-click menu actions use the hovered page/link context; a KDE global shortcut cannot reliably identify a hovered link.
- External Application Launcher uses YouTube document filters and page/frame/link/image/audio/video contexts. Configure existing apps through its options UI to avoid overwriting unrelated extension settings.
- Tampermonkey injects Audio, Video, and Cut buttons between Subscribe and Like/Dislike and sends a `yt-dlp://` URI on a direct click. Its observer reattaches buttons after YouTube SPA navigation/re-rendering.

## Builder calls

- Use the system-installed `mutagen`, Pillow, ffmpeg, yt-dlp, and rsgain; don't install dependencies globally.
- Prefer ordinary date values in container-native tags, not yt-dlp's `YYYYMMDD` upload-date tag.
- Install into the existing `~/.local/bin` and desktop-entry locations only after tests and review; back up existing files before replacing them.
- The extra plan-copy destination was not supplied yet; the canonical plan will be in this repo and the additional copy can be made once the user gives a valid path.
