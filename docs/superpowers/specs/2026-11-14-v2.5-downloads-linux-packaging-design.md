# Firefox YouTube Downloader v2.5.0 — Downloads & Linux Packaging

## Intent

Make video downloads land in a dedicated Videos folder, make audio extraction resilient to yt-dlp sites that only expose muxed audio/video, improve first-run Linux dependency installation, and publish distro-native companion packages alongside the signed extension. Explain the constraints and future options honestly in the README.

## Goals

- Fresh video destination: `~/Videos/Youtube Downloads`; audio destination remains independently configurable. The popup has separate audio/video folder selectors and each supports the current yt-dlp path, the project default, the alternate Downloads preset, or a custom path.
- Audio presets remain `~/Music/Youtube Downloads` (project default), `~/Downloads/Youtube` (alternate), current yt-dlp config, and custom. Video presets are `~/Videos/Youtube Downloads` (new project default), `~/Downloads/Youtube` (alternate), current yt-dlp config, and custom. The selector's "Keep yt-dlp config" persists `null`; if no yt-dlp config exists, that choice falls back to the corresponding project default.
- Preserve existing configs. A missing new `video_download_dir` setting migrates to `~/Videos/Youtube Downloads`; explicit `null` means use yt-dlp's configured path, falling back to that project default when no yt-dlp config exists. Continue preserving `download_dir` exactly as the existing audio setting.
- The new config key and home expansion work on Linux, macOS, and Windows. The existing Windows installer defaults through `save_config()`; no platform-specific installer flow is otherwise redesigned.
- Audio selection uses exact selectors: `bestaudio/best` for `best`, MP3, Ogg, and FLAC; `bestaudio[acodec=opus]/bestaudio/best` for forced Opus; `bestaudio[ext=m4a]/bestaudio/best` for M4A. `-x` then extracts the audio track from a muxed fallback.
- Audio cuts use the same `/best` fallbacks. Opus cuts intentionally bypass yt-dlp's extract-audio pass so the final wrapper can perform exactly one Opus encode; when the cut input is muxed A/V, FFmpeg maps audio streams plus only streams marked `attached_pic`, never ordinary video streams. Preserve metadata and attached cover art where the target container supports it.
- Keep the existing yt-dlp-backed general extractor coverage. Mention `ytgrab-rs` only as a possible, unevaluated future YouTube-only backend; it is not integrated and does not replace yt-dlp.
- Document why audio cuts are offered and video cuts are not: an exact video cut may require re-encoding around keyframe boundaries; stream-copy cuts can be imprecise. This is a product-scope tradeoff, not a claim that video cutting is impossible.
- Add explicit `install.sh --install-deps` support on Debian-family Linux. The flag runs `sudo apt-get update` and `sudo apt-get install` (or runs as root) for `yt-dlp`, `ffmpeg`, `python3`, `python3-mutagen`, and `python3-pil`; automatic tagging stays on. `--with-rsgain` is valid only with `--install-deps` and adds `rsgain`. On non-Debian systems, requesting `--install-deps` exits with a clear unsupported-platform message. Never run a privileged package-manager command unless the user explicitly requests `--install-deps`.
- Release a companion `.deb` for Debian/Ubuntu, a Fedora `.rpm`, and an Arch `PKGBUILD`/`.SRCINFO` recipe archive. Exact dependencies: Debian `yt-dlp`, `ffmpeg`, `python3`, `python3-mutagen`, `python3-pil`; Fedora `yt-dlp`, `ffmpeg-free`, `python3`, `python3-mutagen`, `python3-pillow`; Arch `yt-dlp`, `ffmpeg`, `python`, `python-mutagen`, `python-pillow`. `rsgain` is respectively Debian `Suggests`, omitted from Fedora hard `Requires`, and Arch `optdepends`. The system packages install scripts plus a system-wide Firefox Native Messaging manifest; they must not write to a user's home directory. `install.sh` remains the per-user fallback.
- Package identity is `firefox-youtube-downloader-companion`; version comes from `extension/manifest.json`; Debian architecture is `all`, RPM architecture is `noarch`. Install flat companion files under `/usr/lib/firefox-youtube-downloader/`: `ytdl_config.py`, `ytdl_meta.py`, `ytdl_version.py`, `yt-dlp-wrapper.py`, `yt-dlp-shortcut.sh`, `yt-dlp-native-host.py`. Manifest name is `firefox_youtube_downloader`, `type` is `stdio`, `allowed_extensions` contains `firefox-youtube-downloader@lakis01.github.io`, and its absolute `path` points to `/usr/lib/firefox-youtube-downloader/yt-dlp-native-host.py`. Debian/Arch manifest is `/usr/lib/mozilla/native-messaging-hosts/firefox_youtube_downloader.json`; Fedora manifest is `/usr/lib64/mozilla/native-messaging-hosts/firefox_youtube_downloader.json`. Install the three desktop entries under `/usr/share/applications/`; their `Exec` invokes `/usr/lib/firefox-youtube-downloader/yt-dlp-shortcut.sh` with the existing mode argument. No package lifecycle script creates or edits per-user files.
- Add a tag-push GitHub Actions workflow for `v*` tags. It waits for the maintainer-created **draft** release (containing the matching AMO-signed XPI), builds and attaches the `.deb`, `.rpm`, a tagged source tarball, and the Arch recipe archive, and fails if the version/tag/release is inconsistent. Also allow manual dispatch to build/validate assets without uploading them, so package builds can be checked before creating the release tag. The Arch recipe references the tagged GitHub source tarball with a computed SHA-256 checksum; `.SRCINFO` is generated from the exact recipe. The maintainer verifies all assets before publishing the draft. Do not submit anything to AUR/COPR/OBS automatically.

## Approaches Considered

1. **Keep only `install.sh` and add optional apt automation.** Lowest maintenance, but gives Debian/Fedora/Arch users no native dependency resolution and does not meet the requested release-package workflow.
2. **Native packages for the main desktop package families, plus `install.sh` fallback (chosen).** `.deb` and Fedora `.rpm` declare required/tagging dependencies, Arch receives a user-buildable recipe, and a small tag workflow makes assets repeatable. This uses Firefox's documented system-wide host discovery while preserving the existing user-level installer.
3. **AppImage/Flatpak/Snap plus native packages.** Defer: self-contained/sandboxed formats add host bridge and permission work without removing the required local downloader/FFmpeg dependencies. They are a poor first fit for an extension that launches a local Native Messaging host.

At v2.5.0, do not ship AppImage, Flatpak, Snap, Alpine APK, or Nix packages. Keep the release set intentionally small: `.deb`, Fedora `.rpm`, Arch recipe archive, signed XPI, and source/tag archive. Revisit Nix or other formats when there is a concrete maintainer/user need and a verified Firefox host-registration path.

## Packaging Rules

- Debian package dependencies: `yt-dlp`, `ffmpeg`, `python3`, `python3-mutagen`, `python3-pil`; `rsgain` is a `Suggests` only, not a required or default-installed package.
- Fedora RPM hard `Requires`: `yt-dlp`, `ffmpeg-free`, `python3`, `python3-mutagen`, `python3-pillow`; do not add `rsgain` as a required package. README must explain Fedora's codec-limited `ffmpeg-free` and that users needing additional codecs can install a compatible FFmpeg build from their chosen repository.
- Arch recipe uses the required packages above in `depends` and `rsgain` in `optdepends`.
- Packages are architecture-independent (`all`/`noarch`); put companion files under `/usr/lib/firefox-youtube-downloader/`, desktop entries under `/usr/share/applications/`, and the absolute-path Native Messaging manifest under the documented `/usr/lib/mozilla/native-messaging-hosts/` or RPM `/usr/lib64/mozilla/native-messaging-hosts/` directory.
- A package may install system paths, but never create or modify `~/.config/youtube-downloader`, `~/.config/yt-dlp/config`, Firefox profiles, or per-user Native Messaging manifests. `install.sh` remains per-user and keeps its existing safety guarantees.
- Unlisted AMO signing remains required for the XPI; GitHub release publication is separate. Never log or commit AMO credentials.

## Non-goals

- Implement `ytgrab-rs` integration or a Rust rewrite.
- Add frame-accurate video-cut UI.
- Publish packages to AUR, COPR, OBS, or distro repositories from this project.
- Change Windows/macOS installers except where a shared new config key must be handled compatibly.
