# v2.5.0 Download Progress & Verbose Output — Design

## Intent

Show live yt-dlp progress, transfer rate, and ETA in the terminal opened for a download, while retaining quiet-by-default output. Let users opt into yt-dlp's detailed diagnostic logs from the popup.

## Design

- Keep `--progress` enabled for audio, video, and cut downloads. Quiet mode continues to pass `--quiet`, but the companion drains yt-dlp's stderr pipe as chunks arrive, forwards it to the terminal immediately, and retains a bounded tail for the existing Firefox-cookie authentication retry logic. A pipe is intentional so failures remain classifiable; buffering it until process completion is what currently hides progress.
- Add boolean config `verbose_output`, default `false`. When true, download commands use `--verbose` instead of `--quiet`; progress remains enabled. Older configs without the key stay quiet.
- Add a clearly labelled popup toggle and a note that progress remains visible in quiet mode while verbose diagnostics can include URLs/request details.
- This is terminal progress, not a popup progress bar. The Native Messaging host currently detaches the terminal process and does not stream download events back to the extension; a popup progress bar would be a separate architecture change.
- Do not store or read AMO credentials as part of this work; do not sign or publish a release.

## Alternatives

1. **Forward the existing stderr pipe in real time while preserving a bounded error tail (chosen).** Keeps quiet semantics and authentication retries, with a small reader path in the companion.
2. **Remove `--quiet` by default.** Easier, but leaks extractor and postprocessor chatter for every user, contrary to the user's stated quiet-by-default preference.
3. **Build a popup progress UI.** Requires replacing detached Native Messaging launch with a persistent companion/event channel and reconnection state; larger than this pre-release fix.

## Backlog

Track standalone Windows/macOS companion installers, cross-browser extension shells sharing the Native Messaging backend, and migration guidance when switching between per-user and system package installs in `docs/BACKLOG.md`.
